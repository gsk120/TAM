# AI 분석 PC 프로그램 구동법

## 구성과 준비

웹의 AI 분석 탭 → Cloud Run 작업 저장 → Windows PC의 작업 조회 → Codex CLI → 서버 결과 저장 → 웹 답변 표시 순서다. 완성된 답변을 한 번에 표시한다.

- 서버: 기존 PostgreSQL과 애플리케이션. 이 변경을 포함한 빌드를 배포해야 한다. 이 작업에서 실제 배포는 수행하지 않았다.
- PC: Windows, Node.js 20, 실행 가능한 최신 Codex CLI. 연결 프로그램은 추가 npm 패키지 없이 Node 내장 기능을 사용한다.
- 서버와 PC는 서로 다른 곳에서 실행해도 된다. PC의 포트를 열거나 공유기에 포트 포워딩할 필요는 없다.
- Codex 사용 한도·로그인 상태가 유효해야 한다. 세션 재개 기능 지원과 개인 구독 자동 호출의 허용 여부는 별개다. 구독의 이용 조건은 운영 전에 확인한다. API 과금 방식은 아직 구현하지 않았다.

## 1. 서버 설정

Cloud Run 환경 변수에 다음 값을 설정한다. 로컬 개발에서는 기존 .env에 직접 설정할 수 있다. 실제 값은 Git에 넣지 않는다.

| 설정 | 값 및 의미 |
|---|---|
| AI_ENABLED | true일 때 AI 기능 활성화. 기본값은 비활성 |
| AI_ALLOWED_USER_IDS | 허용할 실제 users.id. 여러 ID는 쉼표로 구분 |
| AI_ALLOWED_USERNAME | ID 설정이 없을 때 서버에서 사용자 ID를 찾는 계정명. 기본 togom |
| DATABASE_URL, JWT_SECRET | 기존 서버 설정 사용 |

AI_ALLOWED_USER_IDS 설정을 권장한다. 화면 노출과 모든 웹·PC 요청은 서버에서 권한을 다시 확인한다. 계정 이름을 바꿔도 ID 허용 정책은 유지된다.

AI 기능의 첫 데이터 요청 시 server/db.js가 ai_records 테이블과 인덱스를 추가한다. AI 대화·메시지·작업·PC·일회성 코드를 kind로 구분하고 사용자 ID에 연결한다. 기존 거래·예산·월별 자산 테이블이나 syncFullDatabase는 변경하지 않는다. DB 계정에는 테이블·인덱스 생성 권한이 필요하다. AI 비활성 상태에서는 AI 테이블 초기화를 실행하지 않는다.

기존 배포 절차에 따라 변경본을 배포한다. 로컬 검증은 프로젝트 루트에서 다음과 같다.

~~~powershell
npm.cmd run check
npm.cmd run dev
~~~

## 2. Codex 준비

먼저 별도 PowerShell에서 다음 명령이 동작하는지 확인한다.

~~~powershell
node --version
codex --version
codex login
codex exec --help
codex exec resume --help
~~~

CLI가 없다면 공식 설치 안내에 따라 설치한다. npm 배포판의 설치 명령은 다음과 같다.

~~~powershell
npm.cmd install -g @openai/codex
~~~

설치·로그인은 사용자가 직접 수행한다. PC 프로그램은 로그인 자격 증명을 서버로 보내지 않고 기존 로컬 Codex 로그인을 사용한다.

- 공식 문서: https://learn.chatgpt.com/docs/non-interactive-mode
- 인증 문서: https://learn.chatgpt.com/docs/auth

## 3. PC 등록 — 최초 한 번

1. togom 계정으로 웹에 로그인한다.
2. 설정 & 백업 → AI 분석용 PC 연결 → 연결 코드 발급을 누른다.
3. 프로젝트 루트에서 아래 명령을 실행하고 코드를 입력한다. URL은 경로 없는 실제 웹 서버 주소로 바꾼다.

~~~powershell
node pc-agent/index.mjs pair https://YOUR-SERVICE.run.app
~~~

코드는 5분간 한 번만 유효하다. 새 코드를 발급하면 기존 미사용 코드는 폐기되고, 새 PC가 등록되면 이전 PC 토큰은 해제된다. 전용 토큰은 Windows 자격 증명 관리자에 저장한다. 서버에는 토큰 해시만 보관한다. 토큰을 명령행·환경 변수·프로젝트 파일에 직접 적을 필요가 없다.

로컬 개발 서버는 아래처럼 연결한다.

~~~powershell
node pc-agent/index.mjs pair http://localhost:8080
~~~

웹의 Vite 주소 대신 API 서버 주소를 사용한다. localhost 외에는 HTTPS만 허용한다.

## 4. PC 프로그램 실행

~~~powershell
node pc-agent/index.mjs run https://YOUR-SERVICE.run.app
~~~

웹의 AI 분석 탭에서 새 대화를 선택하고 질문한다. 현재 조회월이 새 대화의 기본 질문 기준월이 되고, 자료 자체는 본인 계정의 전체 저장 기간이다. 다른 화면에서 조회월을 바꿔도 기존 대화의 기준월은 자동 변경하지 않는다. 다른 기간을 분석하려면 질문에 명시한다.

- PC 작업 조회: 기본 3초, 1분 유휴 후 10초.
- 처리 중: 새 작업 수령을 멈추고 10초마다 생존 신호 전송.
- 웹: 작업 대기 중 2초, 1분 이후 5초 간격으로 결과 확인.
- 동일 PC는 한 번에 하나의 작업을 수행한다.
- 최초 대화: 현재 데이터 + 계산 규칙 + 기존 집계 결과 전달.
- 후속 질문: 해당 대화의 Codex 세션 ID로 재개.
- 세션 기록이 없으면 현재 데이터와 기존 대화 이력으로 새 세션을 구성하고 자료 갱신 안내를 남긴다. 첫 버전은 요약을 새로 생성하지 않고 저장된 대화 원문으로 복원한다.
- 프로그램 종료: Ctrl+C. 처리 중 종료하면 웹에서 생존 신호 누락 후 재질문·재시도를 할 수 있다.

프로그램은 실행 시 PATH의 codex.exe 또는 npm 전역 설치본을 탐색한다. 인식되지 않으면 다음 중 하나를 현재 PowerShell에 설정한 뒤 실행한다.

~~~powershell
$env:AI_CODEX_EXECUTABLE = 'C:\tools\codex.exe'
# 또는 npm Codex의 JS 진입 파일
$env:AI_CODEX_JS = 'C:\path\node_modules\@openai\codex\bin\codex.js'
~~~

CLI는 별도 분석 작업 폴더에서 read-only 샌드박스로 실행하며 개인 config와 실행 규칙 파일은 로드하지 않는다. 구체적인 파일 접근 권한 설계는 PRD의 추후 과제이며, 읽기 전용 설정이 PC의 모든 파일을 비공개로 만든다는 의미는 아니다. 임의 명령 실행을 요청하는 용도로 사용하지 않는다.

## 5. 장애·재시도

- 대기·답변 생성 중에는 같은 대화의 추가 전송·취소·재시도가 차단된다.
- 생존 신호가 60초간 없으면 연결 이상을 표시하고 재질문 또는 이전 질문 재시도를 허용한다.
- PC가 꺼져 있으면 재시도해도 응답은 생성되지 않는다. 먼저 PC 연결 프로그램 상태를 확인한다.
- 재시도는 이전 실행 권한을 무효화한다. 늦게 도착한 이전 답변은 저장하지 않는다.
- PC는 권한 상실을 감지하면 본인이 시작한 CLI 프로세스 트리를 중단하고 정리한 뒤 새 작업을 받는다.
- 정상 생존 신호가 있더라도 CLI가 진행하지 않는 경우가 있을 수 있다. 첫 버전은 자동 무한 재실행이나 강제 재시도 버튼을 제공하지 않는다. PC 프로그램을 종료하고 연결 이상 판정 후 재시도한다.
- CLI 인증·사용 한도·입력 한도 오류는 웹에 실패로 표시된다. PC에서 원인을 해결한 후 새 질문을 전송한다. 오류를 세션 유실로 오인해 자동 반복하지 않는다.
- 이미 생성한 답변은 로컬에 Windows DPAPI로 암호화한 뒤 전송한다. 전송만 실패했다면 AI를 다시 실행하지 않고 결과 재전송을 우선한다. 서버가 실행 만료를 반환하면 이전 결과를 폐기한다.

## 6. 로컬 보관과 연결 해제

- 인증 토큰: Windows 자격 증명 관리자, FamilyFinanceAI로 시작하는 항목.
- 작업 폴더·임시 답변: %LOCALAPPDATA%\FamilyFinanceAI 아래의 서버별 폴더.
- 전송용 전체 스냅샷은 파일이나 서버 DB에 대화별로 누적 저장하지 않는다. 실행 중 메모리에 구성한다.
- Codex 자체의 로컬 세션 기록에는 전달한 가계부 자료와 대화가 남을 수 있다. 이는 웹의 원본 데이터·서버 보관 정책과 별개다. 해당 PC 계정을 안전하게 관리한다.
- 답변 전송이 성공하거나 이전 실행이 만료되면 암호화된 임시 답변 파일을 정리한다.

서버 설정에서 PC 연결 해제를 누르면 토큰을 즉시 사용할 수 없게 된다. PC 인증 정보를 지우는 명령은 다음과 같다.

~~~powershell
node pc-agent/index.mjs forget https://YOUR-SERVICE.run.app
~~~

이 명령은 로컬 토큰만 지운다. 서버 연결 해제도 함께 수행한다. 대화 원문·결과는 서버 DB에 남는다.

PowerShell 스크립트 실행 정책으로 credential.ps1이 차단되면 정책을 우회하는 옵션을 추가하지 말고, PC의 허용된 정책과 파일 신뢰 상태를 확인한다. 코드 검토 후 본인 환경의 정책에 맞게 실행해야 한다.

## 7. 검증 범위와 남은 과제

가상 데이터로 인증·코드 만료·중복 수령·생존 신호 만료·늦은 결과 차단·결과 재전송·세션 연결·기존 집계를 테스트한다. 실제 사용자 DB의 마이그레이션, 실제 Windows 자격 증명 등록, 실제 Codex에 가계부를 전송하는 유료/구독 호출은 별도 운영 확인이 필요하다.

PRD에서 보류한 정상 세션의 자료 갱신, 모델 한도 초과 시 분할 분석, 정교한 실행 권한 설계는 구현하지 않았다. 전체 입력이 모델 한도를 넘으면 실패를 알리며 자료를 조용히 잘라내지 않는다. 향후 API 실행 경로는 확장 지점만 남겨두고 초기에는 local_cli만 실행한다.
